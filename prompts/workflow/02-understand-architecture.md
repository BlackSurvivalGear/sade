# Stage 2 — Understand Architecture

Analyse the existing architecture specifically in relation to the requested change.

Determine how components communicate, where the new functionality belongs, what existing functionality must remain untouched, what can be reused, what new modules are genuinely required, dependency constraints, compatibility requirements, security implications and performance implications.

Do not write implementation code yet.

Produce an architectural assessment covering current architecture, proposed integration point, affected components, deliberately unchanged components, data flow, dependencies, security, performance, risks and recommended implementation approach.

If the request requires an architectural change, explain why before proceeding.
